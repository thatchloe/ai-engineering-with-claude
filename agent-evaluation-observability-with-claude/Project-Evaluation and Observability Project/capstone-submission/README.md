## Status of the System 1 live run (please read first)

**The policy-extractor pipeline command did not run end to end.** The one attempt
(`01-policy-pipeline/pipeline-run-live-attempt-401.txt`) failed with HTTP 401 because the course
key is a Vocareum proxy key and the request went to `https://api.anthropic.com`; the course proxy
base URL was not available on this machine, so no extraction, review or routing was performed by a
model.

**`01-policy-pipeline/routing_decisions.json` and `pipeline-run-offline.txt` are therefore
scenario-driven, not model-derived.** They were produced by `offline_routing_run.py`, which I
wrote. In that script the extractor confidence values and the reviewer agree/disagree verdicts are
inputs I chose (the header and the `SCENARIO` table say which); only the validator, `integration_pass`,
`route_extraction`, `apply_stratified_spot_check` and `write_routing_decisions` are the real
pipeline code. The reviewer disagreement cited in reflection 1b is one of those chosen inputs, not
a signal observed from an independent model.

**I ask for the documented no-API fallback to be accepted** for this item: the course README's
fallback is the routing test suite, captured in `routing-tests-offline-fallback.txt` (9 passed),
which exercises the same `route_extraction` logic with the real code. I understand this is a weaker
submission than a live run. The exact live sequence the reviewer asked for is scripted in
`run-live-pipeline.sh` (project root, next to `calibration_report.py`); it needs only
`ANTHROPIC_BASE_URL` and `ANTHROPIC_API_KEY` from the course workspace and will overwrite
`pipeline-run.txt`, `routing_decisions.json` and `calibration-report.txt` with model-derived output.
